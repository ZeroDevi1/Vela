# TMDB 弱网访问策略

Android 的媒体详情、Seerr Logo、奖项和目录共用 `CatalogNetwork.tmdb`，复用连接池、缓存和故障状态。TMDB 独立于媒体服务器的网络超时设置，不携带媒体服务器凭证。

- 最多同时执行 2 个网络请求；相同路径及参数的查询串行合并，后续调用使用缓存。语言、分页和筛选参数分别缓存。
- 连接超时 2 秒、读写空闲超时 4 秒、单次网络请求及响应读取预算 6 秒。排队时间不包含在单次预算内。关闭 OkHttp 自动连接重试。
- 成功结果在进程内缓存 30 分钟，最多 128 项；成功的空结果也会缓存。进程退出后缓存清空。
- 网络失败、超时、HTTP 429 或 5xx 后冷却至少 60 秒。429/5xx 的数字型 `Retry-After` 按秒读取，冷却上限 1 小时；日期格式回退为 60 秒。排队请求在发起网络访问前再次检查冷却状态。
- 冷却期间不发起新请求；已有且不超过 24 小时的缓存可用于故障回退。没有缓存时目录接口抛出错误，Logo、补充详情和花絮接口沿用可选数据的空值回退；取消操作始终向上传播。401/404 等其他 HTTP 错误不触发全局冷却，也不返回旧数据。
- 冷却结束后的新调用重新尝试，未增加后台轮询。已在途请求不受随后发生的熔断影响。

这能减少中国网络环境中不可达服务引发的重复等待，不能保证 TMDB 官方域名可达。保留官方 HTTPS 地址及证书校验；图片 CDN 请求由现有图片加载器处理，不在上述 API 缓存和熔断范围内。

验证：`./gradlew :data:testAndroidHostTest :data:compileAndroidMain`，覆盖重复请求、批量失败、恢复、旧缓存过期、429 冷却、取消、超时、容量限制和语言/搜索隔离。网络条件通过 MockEngine 模拟，不代表真实国内运营商网络验收。

超时语义参考：[Ktor HttpTimeoutConfig](https://api.ktor.io/ktor-client-core/io.ktor.client.plugins/-http-timeout-config/index.html)。
